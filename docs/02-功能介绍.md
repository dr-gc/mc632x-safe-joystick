# 功能介绍

## 1. 双摄像头采集与双画面展示

两颗 CV2005 摄像头分别采集人体与手部两个视角的画面，经过 VICAP、ISP 和 VPU 处理后，生成用于编码与检测的不同输出。

上位机以两路原视频为主要视图：左画面为手势识别视角，在画面上叠加 21 个手部关节点连线、掌心高亮与摇杆工作区虚线；右画面为人体识别视角，叠加人形检测框与置信度。两个画面均做左右镜像，抬手方向与画面移动方向一致。视频支持单路断流后的自动重连。

当前视频为缩放转码后的预览；手势骨架与视频存在一到两帧的时间差，快速挥手时骨架可能略微滞后。

## 2. 双路网络视频传输

板端分别对两路视频进行 H.264 编码，并提供独立的 RTSP 服务。默认端口为：

| 视频来源 | RTSP 端口 |
|---|---|
| 摄像头 G0（人体识别） | 1246 |
| 摄像头 G1（手势识别） | 1252 |

PC 可以分别拉取两颗摄像头的画面，用于确认哪一路是手、哪一路是人。为了在浏览器中直接显示视频，PC 端使用两条 ffmpeg 管线将 RTSP 直接转为 MJPEG 字节流，通过同源 MJPEG 接口提供给网页，Python 侧只做 JPEG 边界切分，不做解码重编。两路视频分别维护连接状态，支持单路断流后的重连。早期方案曾在 Python 内解码后重编码，受 GIL 限制仅有 10.5 fps；改为直出后达到 55 fps。

## 3. 板端 NPU 人形检测

板端利用 SDK 提供的人形检测模型（30055），在一个 NNA 工作线程上对摄像头 G0 的画面执行推理，输出当前人数、位置框与置信度，经串口以 [BOX] / [ROD] 格式上报。

模型以 .incbin 方式内联进固件 .data 段，不依赖文件系统；配套在 nna_config.c 中标记 model_from_mem，跳过对静态内存的释放。

PC 端解析串口数据后，在右画面上绘制人形框。检测结果与视频传输分开处理，两者独立维护状态。

当前模型为厂商提供的通用人形模型，实测在 174 帧中检出 119 帧（68.4%），置信度前十均高于 0.95。侧身、遮挡、逆光场景检出率会下降。

## 4. 手部 21 关键点跟踪

PC 端使用 MediaPipe Hand Landmarker 对摄像头 G1 的画面提取手部 21 个归一化关键点，输入分辨率 480×270，实测 12~14 fps，支持双手同时检测。

关键点坐标以手腕为原点、按手部尺寸归一化后，可直接用于骨架绘制、手势分类与摇杆映射三处，不需要各自单独标定。检测阈值经过实测调整：min_hand_detection_confidence 设为 0.15（默认 0.5 时手稍远即丢失），presence 与 tracking 保持 0.35 和 0.30 以抑制背景误检。三阈值同时降到 0.01 会引入大量误检，全部设为 0 会导致 MediaPipe 内部断言崩溃。

当前跟踪针对单手型、单向距离优化，手距摄像头超过约 1.5 米时检出率明显下降。

## 5. 手势识别与安全分级

PC 端将 21 个关键点输入预训练 MLP 分类器，识别张开手掌、握拳、指向前三类手势，离线验证集 4450 条真实样本准确率 96.52%。

手势不是直接触发动作，而是进入四态安全状态机：

| 状态 | 触发条件 | 输出 |
|---|---|---|
| 待机 | 未检测到手或手不在工作区 | 停止 |
| 就绪 | 手在工作区但在死区内 | 停止 |
| 运行 | 偏移超过死区 | 方向指令 |
| 急停 | 张开手掌 | 停止并锁存 |

早期曾用手写几何规则判断握拳（指尖到掌心距离比掌宽），实测会把半张的手误判成握拳，导致频繁误触急停。改用模型后，误判方向从误触发变为漏报，对安全功能来说这是正确取舍。

当前只识别三类手势，尚未支持更复杂的手势组合。

## 6. 八方向摇杆与零点校准

PC 将掌心位置相对零点计算偏移，通过反正切函数把平面切成 8 个 45° 扇区，映射为前进、后退、左转、右转及四个斜向共 8 条指令。

例如，手位于零点右上方 30°、偏移量为 500 时，输出右前指令；手回到距零点 8% 以内时，输出停止。

防抖由三层构成：死区 8%（偏移小于工作区半宽 8% 时视为停止）、幅度门限 60/1000（轻微偏移不触发运动）、低通滤波（α=0.4，输出平滑无跳变）。

摄像头没有机械中位，因此提供零点校准：连续握拳 3 次，取三次掌心位置的平均值作为新的停止位，用户可以用最舒服的姿势作为原点。

当前零点基于画面坐标，摄像头被碰歪后需要重新校准。

## 7. 小车控制指令与心跳保活

摇杆输出经 TCP 通道下发给执行端，Linux 作服务端，执行端主动连接 9000 端口，协议为纯文本行。指令只在方向变化时更新，但每 0.5 秒心跳重发当前指令。这是因为执行端配有 3 秒断流看门狗：如果只在变化时发送，小车会在 3 秒后误判超时自动刹车；改为心跳后，既保证控制连续，又能在上位机真正崩溃时正常刹车。

| 指令 | 动作 | 摇杆方向 |
|---|---|---|
| w | 前进 | FWD |
| wr / wl | 右前 / 左前 | FWD_RIGHT / FWD_LEFT |
| d / a | 右转 / 左转 | RIGHT / LEFT |
| sr / sl | 右后 / 左后 | BACK_RIGHT / BACK_LEFT |
| s | 后退 | BACK |
| stop | 停止 | 死区 / 急停 |

同时提供 UDP 广播通道（20 Hz，JSON 格式），用于不需要握手的场景。当前仅在 Gazebo 差速仿真上验证，尚未在真实小车上测试。

## 8. 本地网页与状态可视化

PC 服务使用 Flask 实现，浏览器打开本地页面即可查看双路视频、手部骨架、摇杆状态、手势识别结果与系统日志。

界面每秒轮询 11 次状态接口，右侧信息栏分为四张卡片：人体检测（状态、目标数、置信度、串口连接）、手势识别（手势名、手部数量、左右手、检测帧率）、安全状态（四态）、系统日志（滚动输出）。

页面区分四种情况，避免把没有有效数据误显示成正常：

| 情况 | 界面表现 |
|---|---|
| 检测正常，未检测到手 | 待机（灰）|
| 检测正常，手在控制 | 运行（绿）|
| 串口/网络断开 | UART OFFLINE / LINK LOST |
| 数据过期 | 指标归零并提示 |

当前界面针对 1920×1080 及以上分辨率设计，未做移动端适配。

## 9. VOU 屏显输出

板端通过 VOU 通道驱动 AT070TN94 屏（800×480 RGB 并口）。

修复的四个配置问题：DEVICE_DHD0 未开启、YCMEAN_EN_G0 占用 loop buffer、CH1_ENABLE_G0 未开启、OSD 初始化失败导致 demo 中止。屏驱动误选问题通过二进制补丁 libvou.a 修正（read_tab_index 返回 1 走 RGB 分支），现可正确识别为 rgb_AT070TN94_800x480。

当前驱动识别、时序参数、VOU 通道使能均正常，帧计数 FrmRevCnt = FrmDisCnt 无丢帧，但面板不显示画面。已排除软件因素，判定为排线或面板数据线硬件问题。本次展示不依赖该屏。

## 完整操作时序

一次从站到镜头前到小车停下的完整流程：

| 步骤 | 动作 | 系统行为 | 耗时 |
|---|---|---|---|
| 1 | 操作者进入 G0 视野 | 板端 NPU 检出人形，conf ≥ 0.92 | ~200 ms |
| 2 | 操作者把手伸到 G1 前 | MediaPipe 锁定手部 21 关键点 | ~70 ms |
| 3 | 掌心进入摇杆工作区 | 状态机由待机进入就绪 | ~70 ms |
| 4 | 手向目标方向偏移 | 偏移超过死区，置为运行并算出八方向 | ~70 ms |
| 5 | 指令下发 | 检测到方向变化，经 Unix socket 传出 | <5 ms |
| 6 | 心跳发送 | 每 0.5 秒重发当前指令 | ≤500 ms |
| 7 | 小车运动 | 仿真机发布 /cmd_vel | 40~80 ms |
| 8 | 手势变化 | 方向变化时立即下发新指令，不等心跳 | — |
| 9 | 张开手掌 | 状态机置为急停，立即下发 stop | <70 ms |
| 10 | 小车停止 | /cmd_vel 归零 | — |

端到端延迟（步骤 4 到步骤 7）为 40 到 80 ms。

三种异常收敛路径：

| 异常 | 系统响应 | 响应时间 |
|---|---|---|
| 手离开 G1 视野 | 偏移量平滑衰减至 0，下发 stop | ~150 ms |
| 张开手掌 | 立即 stop 并锁存，手离开才解除 | <70 ms |
| 网络断流 | 对端 3 秒看门狗自动刹车 | 3 s |

## 操作手册

启动顺序：

```bash
# 1. 板子上电，等待 10 秒
# 2. 确认串口
ls /dev/ttyUSB*

# 3. 启动 TCP 服务端
cd ~/mc630x_rtthread/host
python3 tcp_ctrl_hb.py

# 4. 启动上位机（另开终端）
python3 web_host.py

# 5. 浏览器打开
firefox http://localhost:8765

# 6. 仿真机连接 192.168.0.114:9000
```

日常操作：

| 想做的事 | 操作 |
|---|---|
| 控制小车前进 | 手移到画面上方，保持 |
| 让小车停 | 手移回摇杆中心（死区内）|
| 急停 | 张开手掌 |
| 设定新的停止位 | 点校准摇杆，连握 3 次拳 |
| 恢复默认零点 | 点重置按钮 |
| 暂停控制 | curl -X POST http://localhost:8765/api/carlink/enable/0 |

常见问题：

| 现象 | 原因 | 解决 |
|---|---|---|
| 一直显示待机 | 手不在 G1 画面内 | 看左画面，把手伸进去 |
| 摇杆乱跳 | 手抖或光照变化 | 调大 joystick.py 的 dead_zone |
| 骨架不显示 | Canvas 绘制异常 | 检查浏览器控制台 window.__ov1Err |
| UART OFFLINE | 串口设备名变化 | 已改为自动探测，重启后端 |
| 小车不动 | TCP 未连或指令未达 | ss -tn 查看 9000 端口连接 |
| 视频卡顿 | 板端 ISP 6.55 fps 限制 | 见项目概述的已知限制 |
